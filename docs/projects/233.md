# Project brief — Export and the printable summary: CSV presets for a buyer and for the owner, and a one-page summary

The mandate is [#233](https://github.com/yedeya/plinthos/issues/233): `HANDOVER.md` §9 milestone 6 as §4.4 describes it, on the Owner's decisions of 2026-11-03, without the barcode scan (#234). The brief seeds a new spec area, `docs/qa/specs/export.md` (`EXP`, 5 clauses). Every clause is `[seed]`. Like #207 and #226, this is a compact brief, built by local agents.

## 1. The real problem

**The collection can't leave the app except as the public catalogue.**
- **No list:** a selling platform wants a list pasted or attached, and the owner wants a record of their own. Nothing exports one (`git grep -n "text/csv" -- src` finds only the parts download, `[PUB-20]`).
- **Nothing to print:** the catalogue is a set of web pages with photos, not a page for a buyer's folder.

**Two traps the clauses close:**
- **A buyer's file must not carry a private field,** and neither must the summary. Both are built from the projection the publish step uses (`[PUB-5]`), so they hold what the catalogue would publish now and nothing more, and `[PUB-4]`'s canary test runs over both, under every combination of the settings (`[EXP-2]`, `[EXP-5]`). The full preset reads the database, but it is only a download from `/admin`, never cached, never linked (`[EXP-3]`).
- **A CSV is code to a spreadsheet.** A description or a missing-parts note that starts with `=` runs as a formula when the file is opened. Every cell that could is escaped (`[EXP-4]`).

## 2. Scope

**This project is:**
- the two CSV presets, *for a buyer* and *full*, as downloads from `/admin`;
- `/admin/summary`, the one-page printable summary, with its print stylesheet;
- the route and canary tests that cover them.

**It is not:**
- **The barcode scan.** It is #234, an idea in the backlog.
- **A parts lot as a CSV row.** The parts list is `[PUB-20]`'s download, and the summary counts the lots and parts.
- **A PDF.** The browser prints the summary, or saves it as a PDF itself (`HANDOVER.md` §4.4: "HTML print stylesheet is enough").
- **A public summary page.** The summary sits behind the admin login. The owner prints it or saves it and hands it on.
- **An import of a CSV.**

## 3. Decomposition

### Issue A — Export the collection as CSV for a buyer and in full, and print a one-page summary
**Milestone:** Product Backlog · **Labels:** `enhancement`

This item builds:
- **The projection:** the one function that builds the public catalogue data, callable without the publish step's turn and token, so the buyer preset and the summary use exactly what a publish would. The publish step keeps calling the same function (`[PUB-5]`). The export gets the `PublicCatalogueData` alone, never an issued `PublicProjection` or its `photoCopies` (which hold the stored keys), so `assertPublicProjection` still tells a publish from an export.
- **`src/server/export/`:**
  - `exportCollection(admin, { preset })`, an `adminOperation` with zod input, which returns the file name and the CSV text;
  - a pure CSV writer (`[EXP-4]`), tested on its own, formula escaping included;
  - `export.downloaded`, logged with the preset and the row count, with a row in `docs/observability.md`'s not-paged table.
- **`/admin`:** two download links, **CSV for a buyer** and **Full CSV**, and a link to the summary. The full one says it holds private fields.
- **The routes:** the downloads as admin route handlers, with `Content-Disposition: attachment` and `Cache-Control: no-store`, added to the route test that refuses an anonymous request.
- **`/admin/summary`:** server-rendered from the public catalogue data, with a print stylesheet that fits one A4 or Letter page and a **Print** button.
- **`[PUB-4]`:** the canary test also checks the buyer CSV and the summary's HTML under every combination of the settings.
- **`docs/qa/stack.md`'s `## Data isolation`:** a line for the full preset, a new reader of private columns that only an admin download reaches.
- **`docs/security-review.md`:** a dated pass, because this adds routes that read private data and a second reader of the projection.

## 4. Cost

**$0 a month more.**
- The downloads and the summary run in the admin's existing server function, only when the owner opens them.
- Each wakes Aurora as any admin view does, for a few queries.
- They add no resource, no schedule and no alarm (`AGENTS.md` §3).

## 5. Observability

- **Add, not paged:** `export.downloaded`, with the preset and the row count, and never the content, with a row in `docs/observability.md`'s not-paged table. It records an action the owner just took.
- **No alarm.** A failed export shows on the screen at once, as any failed admin request does (`admin.request.failed` with its request id). Paging it would cost about $0.10 a month, for a failure the owner is looking at.

## 6. Blast radius — what will need a human

- **`src/server/publish/projection.ts`** (`other`): the projection becomes callable outside the publish step's turn. `[PUB-5]`'s import scan and `[PUB-4]`'s canary are held in `docs/qa/stack.md`'s `## Data isolation`. The full preset is a new reader of private columns, so that section gains a line for it.
- **No schema change and no migration.**
- **No `infra/` change.** The routes are part of the admin.

## 7. Decisions

Answered by `@yedeya`, as Owner, on 2026-11-03:

1. **The CSV export. ✅ Two presets:**
   - *for a buyer*: the public fields, plus values and asking prices only where the catalogue shows them;
   - *full*: every field, private ones included, for the owner's own records.
2. **The printable summary. ✅ It follows the catalogue,** and is safe to hand to a buyer.
3. **The barcode scan. ✅ Left out,** and filed as #234.
4. **The Lead's technical choices, under 1 to 3:**
   - UTF-8 with a byte-order mark and comma separators, which spreadsheet programs open as they are;
   - formula escaping with a leading `'`;
   - booleans as `yes` and `no`;
   - one row per item, loose parts lots excluded;
   - one A4 or Letter page, with no photos, so it prints in black and white on one sheet;
   - no asking-price column in the buyer CSV, because an asking price belongs to a segment or the whole collection, not an item. The summary shows the asking prices;
   - no notice of changes since the last publish, because no publish time is stored and storing one would need a migration. The summary says it shows the catalogue as a publish would make it now.

## 8. What I did not examine

- **The summary's fit on one page with a long intro or contact text.** Issue A clips neither. If they push the summary onto a second page, it says so in its PR.
- **Excel's handling of the byte-order mark on every platform** is recalled, not tested: Excel on macOS and on Windows, Numbers and LibreOffice open such a file as UTF-8.
