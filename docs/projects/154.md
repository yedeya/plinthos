# Project brief — Public catalogue: the shareable showcase of the collection

The mandate is [#154](https://github.com/yedeya/plinthos/issues/154): `HANDOVER.md` §9 milestone 4, as a showcase without values. The Owner put selling mode, values and the parts download with milestone 5 (2026-11-02). Seven clauses join `docs/qa/specs/publish.md` (`PUB-9` to `PUB-15`), every one `[seed]`. The visitor's design is `docs/design/catalogue.md`. Like #124, this is a compact brief, and local agents build it.

## 1. The real problem

**The snapshot publishes nothing.** `publishCatalogue` writes a placeholder that says nothing is published yet: `git grep -n "nothing is published yet" -- src/server/publish/`. The projection reads only the token, and no admin page sets the texts a visitor reads. The pipeline is sound and held by tests: one projection (`[PUB-5]`), no private field in any setting (`[PUB-4]`), a bucket-only distribution with `noindex` (`[PUB-1]`, `[PUB-2]`), and taking turns (`[PUB-8]`). So this project fills that pipeline with content. It changes none of its guarantees.

**Two traps the clauses close:**
- **A public photo must not be a private file.** If the snapshot named the private stored keys, or linked them through a presigned URL, the private bucket would be one leaked link away. So each published photo is a copy under the token, with a new random key (`[PUB-13]`), and the private bucket stays served by nothing.
- **A rotated token must really end the old link.** Rotation deletes the old prefix and invalidates it (`[PUB-15]`). Otherwise a link once shared would keep working from CloudFront's cache or from S3.

## 2. Scope

**This project is:**
- the settings page with the intro and contact texts;
- the projection's content: items, sets, photos, texts and the parts summary;
- the public photo copies;
- the landing, grid, detail and parts pages, with the filter and sort script;
- token rotation;
- the first `docs/security-review.md`, which `AGENTS.md` §1 requires before the link is first shared.

**It is not:**
- **Values, asking prices, totals by value, a sort by value, split views, selling mode or the parts download.** These come with milestone 5 (decision 2). `show_values`, `selling_mode` and `selling_value_display` stay off and private, and the projection still reads none of them.
- **A custom domain, analytics or a contact form** (brief #6 decision 8; `HANDOVER.md` §10.9: text only).
- **Translations.** Every public string goes in a message file, so a translation is a later addition (`HANDOVER.md` §10.9).

**Definition of done:** the Owner presses Publish, and the shared link shows the collection with its photos. Before it is shared, `docs/security-review.md` has no open Critical or High finding.

## 4. Cost

**About $0 to $0.05 a month.** The public photo copies double the photos' storage in S3, at about $0.023 per GB-month, so cents for a few hundred photos. CloudFront serves them inside its free tier of 1 TB a month. A publish copies objects inside one region, which costs nothing for the transfer and fractions of a cent for the requests. It runs only when the Owner presses Publish, and wakes Aurora as an admin request does. Nothing runs on a schedule.

## 5. Observability

- **Keep, not paged:** the existing `businessEvent`s `catalogue.published` and `catalogue.publish.failed`, which now also log how many items and photos a publish wrote. A failed publish shows on the page and leaves the previous catalogue online (`[OPS-6]`).
- **Add, not paged:** the `businessEvent` `catalogue.token.rotated`, with a row in `docs/observability.md`'s not-paged table. It records an action the owner just took (brief #6, §5's reasoning). A rotation the owner didn't make would change the answer, and that is a separate signal, not added here.
- **No alarm.** Paging any of these would cost about $0.40 a month each, for actions the owner starts and sees.

## 8. What I did not examine

- **How many photos a publish copies, and how long that takes.** At 140 sets with about 4 photos each, a publish copies about 1,100 objects. Copies run in parallel, a few dozen at a time, so this should fit the server function's time limit, but nobody has measured it. If it doesn't, Issue A copies only new photos, keyed by the private key's hash, and says so.
- **CloudFront's invalidation of a whole prefix on rotation** (`/c/{old}/*`). It's recalled as one wildcard path and free up to 1,000 paths a month. Issue A checks that.
