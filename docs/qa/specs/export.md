# Export

The owner's downloads and the printable summary (`HANDOVER.md` §4.4). Seeded by the export project (#233). Every clause is `[seed]` until a human promotes it (`K-SPEC-8`).

**Id prefix:** `EXP`

## The two CSV presets

- `[EXP-1]` `[seed]` `/admin` offers the collection as a CSV file in two presets, and only an authenticated admin can download either: an anonymous request is refused like every admin route (`[AUTH-3]`), and the route test lists both. Each answer is a download (`Content-Disposition: attachment`) that no cache keeps (`Cache-Control: no-store`), and the admin logs `export.downloaded` with the preset and the row count, never the file's content.
- `[EXP-2]` `[seed]` The **for a buyer** preset is built from the public catalogue's data, through the one function that builds the publish step's projection (`[PUB-5]`), with the settings as they are now, never from the database directly. It has one row per published item, with the item's public fields as the catalogue holds them: kind, set number, name, reference number, theme, year, the number of parts, the approximate parts and weight, the condition, complete, the missing parts, the instructions, the description and the quantity. Its value, as-of date and currency columns are there only when the catalogue shows the items' market values (`[PUB-17]`), and are otherwise absent, not empty. It has no asking-price column: an asking price belongs to a segment or the whole collection, never to an item (`[PUB-18]`), so the summary shows them (`[EXP-5]`). `[PUB-4]`'s canary test covers it under every combination of the settings.
- `[EXP-3]` `[seed]` The **full** preset holds every item with every field the owner entered, private ones included: the storage location, the manual value override and its currency, and the item's value with its source and date (`[VAL-5]`), plus the created and updated times. It is the owner's own record and is never published, linked from the catalogue, or cached. A loose parts lot is not a row in either preset: the parts list is `[PUB-20]`'s download.
- `[EXP-4]` `[seed]` Both files are UTF-8 with a byte-order mark, comma-separated, CRLF line ends, a header row and RFC 4180 quoting, so spreadsheet programs open them as they are. Amounts are plain decimals with a dot and no thousands separator, dates are ISO 8601, and booleans are `yes`, `no` or empty. A cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return is written with a leading `'`, so no spreadsheet runs it as a formula. The file name says the preset and the date, such as `plinthos-buyer-2026-11-03.csv`.

## The printable summary

- `[EXP-5]` `[seed]` `/admin/summary` is a one-page summary, made to print on one A4 or Letter page with a print stylesheet. It is built from the same public catalogue data as the buyer preset, never from the database directly, so it shows exactly what the catalogue would show now: the intro text, the contact text, the number of items per segment (sealed, used, and the loose parts' lots and parts), and the values, totals and asking prices only where the settings show them. It carries the date and time it was made, and says that it shows the catalogue as a publish would make it now, which can differ from the catalogue last published. It shows no photo, no catalogue link or token, and no private field, and `[PUB-4]`'s canary test covers it.
