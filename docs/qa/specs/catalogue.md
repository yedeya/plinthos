# Set catalogue

How the admin finds a LEGO set and fills in its details from the Rebrickable catalogue (`HANDOVER.md` §4.1). Seeded by the set-entry project (#124), with the set index added by #252. Every clause is `[seed]` until a human promotes it (`K-SPEC-8`).

**Id prefix:** `CAT`

## Lookup

- `[CAT-1]` `[seed]` The admin can search sets by set number or by name through an admin route that refuses an anonymous request (`[AUTH-3]`) without touching the database or Rebrickable (`[AUTH-6]`). A query shorter than two characters returns nothing and calls nothing. A search returns at most 10 sets, each with its set number, name, theme, year, piece count and stock image URL.
- `[CAT-2]` `[seed]` Every Rebrickable request goes through one client that sets a timeout of at most 5 seconds, sends at most one request per second from each server instance, and retries a 429 or 5xx answer at most twice with exponential backoff that honours `Retry-After`. It never retries past the caller's time budget, and it never logs the API key or a URL that carries it. A call whose request the browser has aborted sends nothing, stops waiting for its slot, and is not logged as a failure.
- `[CAT-3]` `[seed]` A set that has been looked up is stored in the `lego_set` table, with a UUID primary key (`[PLAT-13]`) and the set number as a unique key that every lookup and the items' foreign key use: name, theme name, year, piece count, stock image URL and when it was fetched. A lookup of a set number fetched in the last 30 days reads the table and makes no Rebrickable request. A search reads `lego_set` first. A search for a typed set number whose set it holds, fetched in the last 30 days, answers from the table and makes no Rebrickable request; any other search asks Rebrickable, and stores every set it returns, merged with the table's by set number.
- `[CAT-4]` `[seed]` The Rebrickable API key is the SST secret `RebrickableApiKey`, named in `docs/deploy.md` (`[PLAT-3]`). It is read only on the server and never reaches the browser, a log line, the public snapshot or the offline queue.
- `[CAT-5]` `[seed]` When Rebrickable fails, times out or refuses the key, a search never answers an error page: it answers the sets `lego_set` holds for the query, and the set the direct lookup found, marked `partial`, or `unavailable` when there are none. The entry form says quietly that search isn't answering, and still saves a typed set number from the same field. A lookup failure never refuses a sign-in or any admin page.

## The set index

Seeded by the set index project (#252): a search index of Rebrickable's sets and minifigures, built weekly from its free downloads and searched on the phone.

- `[CAT-6]` `[seed]` The set index is built by one function, `buildSetIndex`, from Rebrickable's `sets.csv.gz`, `themes.csv.gz` and `minifigs.csv.gz` alone. It holds each set's number, name, theme id, year and piece count, and its stock image path only where it differs from `<set number>.jpg`; each minifigure's number, name and piece count; every theme's id, name and parent id; when it was built; and each source file's `Last-Modified`. It holds nothing from the database: the builder's function is linked to no database and no secret, and a test asserts that `buildSetIndex` imports nothing from `src/db/` and that an index built from made-up fixtures holds only these fields.
- `[CAT-7]` `[seed]` Each download has a timeout of at most 30 seconds, is retried at most twice with exponential backoff on a network failure, a 429 or a 5xx, and is refused past a size cap, compressed and decompressed alike. A row that doesn't parse is skipped and counted. A build whose sets or minifigures number fewer than 90% of the previous index's, or that fails in any other way, writes nothing and leaves the previous index in place. An index is written under a key named by its content hash, so an unchanged build writes nothing new. A build logs `set_index.built`, with the counts, the skipped rows, the size and the version, or `set_index.build.failed`, with the stage and the reason.
- `[CAT-8]` `[seed]` The builder runs once a week from a schedule, and never reaches Aurora. It downloads only Rebrickable's archive files, never a Rebrickable web page, and a build started within a day of the last download fetches nothing (Rebrickable allows automated downloads at most once a day). It may write, read and delete only under the index's prefix of the private photo bucket, which nothing serves. No public distribution serves the index, and no page of the public catalogue names it.
- `[CAT-9]` `[seed]` `GET /admin/api/sets/index` is an admin route that refuses an anonymous request (`[AUTH-3]`). It answers the current index, gzipped, with its version as the `ETag` and `Cache-Control: no-store`, answers 304 to an `If-None-Match` that names the current version, and answers 404 while no index has been built.
- `[CAT-10]` `[seed]` The entry form keeps the index in an IndexedDB database of its own on the device. When the admin opens online, it asks the route once, with the version it holds, and downloads the index only when the version changed. It replaces the stored index only once the new one is fully read and parsed, so a failed download keeps the old one. The service worker caches it nowhere (`[SYNC-6]`), and logout deletes it with the queue (`[SYNC-9]`). `/admin` shows when the index on the device was built, and says so when it is older than 14 days.
- `[CAT-11]` `[seed]` With an index on the device, the set field searches it as the owner types, sets and minifigures together, ranked by the rules of `rankSets`, at most 10, each with its number, name, theme and year, and sends no request. It asks the server's search (`[CAT-1]`) only when the device has no index, when the text reads as a set number the index doesn't hold, when a name finds nothing in it, or when the owner presses **Search Rebrickable**. Offline and on the offline shell, the index answers and nothing is sent. A picked set saves its set number, and its `lego_set` row comes from one lookup when it syncs, as `[ITEM-4]` says: nothing from the index fills `lego_set`. A picked minifigure turns the form into a Minifigure with its name filled in (`[ITEM-10]`), and leaves the reference number empty, because BrickLink numbers minifigures differently from Rebrickable.
